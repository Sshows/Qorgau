# Реальные публичные камеры QORGAU

Проверка источников: **3 ноября 2026, 15:16–15:24 UTC**. Исследованы **28 конкретных источников**. Каталог `verifiedCameraCatalog` содержит **27 источников**: 20 HLS-видео и 7 обновляемых снимков. Один YouTube-источник исключён: при браузерной проверке YouTube сообщил «Запись этой трансляции недоступна». В каталоге нет DEMO-записей или чисел, скопированных из счётчиков сторонних сайтов.

Полные результаты транспортной проверки с URL и временем: [camera-source-checks-2026-11-03.json](./camera-source-checks-2026-11-03.json). Запрос сегмента ограничен первыми 1024 байтами; проверен MPEG-TS sync byte. Это доказывает доступность media data, но не декодирование и воспроизведение браузером. В плейлистах присутствовали актуальные `EXT-X-PROGRAM-DATE-TIME`; время публикует оператор.

Анализ первых 256 КБ media segment всех **20 HLS** подтвердил PMT stream type `0x1b` (H.264/AVC); SPS соответствует CODECS в манифесте. Ни у одного источника не обнаружен HEVC. Все master playlists предлагают одну variant rendition, альтернативы с меньшим разрешением в этих манифестах нет. Это проверка контейнера/метаданных, а не доказательство декодирования браузером. У XCOM `13-1` обнаружены фрагменты длиной около 34 секунд; остальные XCOM публикуют примерно 5–8 секунд. Ранний 25-секундный watchdog мог прервать медленное подключение; теперь старт ограничен 90 секундами, `fragLoadPolicy` в hls.js 1.7.3 задаёт first-byte 60 секунд / общий load 90 секунд. Отмена доступна пользователю. Несколько одновременных 1440p потоков могут потребовать значительной пропускной способности.

Браузерная проверка основным агентом подтвердила декодирование трёх Шымбулак и XCOM `12-55`, `caspy14` (2560×1440). У других тестировавшихся потоков встречались ошибки старта; HTTP 200/206 не используется как доказательство воспроизведения. Ни неисправность кодека, ни универсальная совместимость всех 20 потоков не утверждаются.

Все записи изначально имеют статус **«Не проверена»** и `checked_at: null`. HLS становится «Доступна» только после события `playing` браузера. Снимок становится «Доступна» после успешной загрузки изображения; интерфейс прямо сообщает, что это не прямое видео. YouTube iframe не меняет статус только по факту открытия. Транспортное время хранится отдельно в `transport_checked_at`; оно не выдаётся за текущую проверку воспроизведения.

## Откуда взяты URL

- [Шымбулак — официальный раздел камер](https://shymbulak.com/live/): сохранены прежние три HLS URL `ipcam.kz`, камеры cam1/cam5/cam6.
- [PocketWorld — Казахстан](https://pocketworld.org/ru/webcams/country/kz): опубликованы 17 конкретных публичных URL оператора `cam.xcom.kz:8081`. Каждая запись содержит ссылку на соответствующую карточку каталога. Каталог не считается официальной городской системой наблюдения.
- [OSIRIS API documentation](https://osirisai.live/docs), публичный `GET https://osirisai.live/api/cctv`: дополнительная сверка девяти XCOM камер, семи Windy снимков и YouTube ID. В ответе встречается `feed_url` для снимков и `stream_url` для видео; эти форматы не смешиваются.
- [Windy](https://www.windy.com/webcams): в каждой записи есть собственный ID камеры, `images.current`, `location`, `lastUpdate`, `pageUrl`. Публичный endpoint без ключей: `https://node.windy.com/webcams/v2.0/detail/{cameraId}?imageSize=full&lang=en`. В приложение скопированы только постоянные публичные адреса изображений; краткоживущие embed-токены не используются.
- [meteoblue — камеры Алматы](https://www.meteoblue.com/en/weather/webcams/almaty_kazakhstan_1526384): независимо сверены подписи и координаты нескольких местных Windy камер.

XCOM slug: `13-1`, `12-55`, `19-1`, `4abrease`, `28ring`, `9ring`, `11ring`, `amfiteatr15a`, `amfiteatr15b`, `amfiteatr15c`, `amfiteatr15-10`, `caspy1`, `caspy14`, `caspy15`, `rockypath`, `yntymak`, `dramteatr`. У каждого URL фактически проверены master, variant и media segment; записи не являются просто ссылками на каталог.

## Координаты и время снимка

На карту переданы **семь опубликованных Windy координат конкретных камер**. В паспорте прямо указано: координаты публичного каталога, точность места установки владельцем не подтверждена. Источник координат — индивидуальный JSON metadata URL, зафиксированный в проверочном файле. Для Алматы/области некоторые значения также совпадают с `data-coord` meteoblue.

Для 17 XCOM и трёх Шымбулак координаты оставлены `null`: приблизительные точки стороннего агрегатора и центр курорта не используются как места установки камер. Районы Алматы не назначаются камерам Актау или области. На карту не добавлены искусственные точки.

`lastUpdate` Windy зафиксирован как **время обновления, сообщённое Windy на момент проверки**, а не как время камеры. Текущее время загрузки снимка показывается отдельно. При просмотре снимок запрашивается каждые 60 секунд; это не гарантирует новую съёмку у владельца. Старый кадр нельзя считать свежим только потому, что HTTP вернул 200.

## Исследованные ограничения

- [ARGOS ATLAS — Казахстан](https://argosatlas.com/en/cameras/kazakhstan/) сообщает о 38 точках, преимущественно still images. Эти числа не перенесены в QORGAU, и внешняя страница не посчитана одной или несколькими подключёнными камерами. Конкретные общедоступные URL проверяются отдельно.
- [Oi-Qaragai — официальный раздел](https://oiqaragai.com/ru/live): старый конкретный HLS `s173.ipcamlive.com/streams/adthvf6i5watr07de/stream.m3u8`, обнаруженный в каталоге, возвращает HTTP 404. Он исключён из доступных видео. Три актуальных снимка региона добавлены через публичные Windy feeds с ссылками владельцев.
- [cam-world — Алматы](https://cam-world.ru/geo/asia/kazahstan/almaty): найденные видео повторяют существующие Шымбулак/YouTube, поэтому не добавлены дублями.
- PocketWorld включает ошибочные country tags у отдельных российских камер. Они отсеяны; чужие города не выданы за Казахстан.
- Часть старых XCOM страниц сайта оператора возвращает 410; действующие HLS endpoints проверены напрямую. Исходная карточка PocketWorld и реальный hostname оператора сохранены раздельно в записях/этом документе.

## Реализованный просмотр

Город/регион, район, категория, формат, доступность, поиск, сортировка, избранное с локальным хранением, сетка/список/видеостена/карта, увеличенный просмотр, fullscreen и следующая камера. Фильтры сохраняются в session storage, избранное — в versioned local storage. Выбор новой камеры отключает прежний поток. HLS, iframe и снимки в плеере подключаются действием пользователя; запросы плеера останавливаются при закрытии. Карточки трёх Шымбулак и семи снимков лениво загружают реальные публичные preview JPEG/изображения с явной подписью, что кадр не подтверждает эфир. Для XCOM preview.jpg вернул 404 — там остаётся подписанная схема без фиктивного видеокадра.

Администраторская форма остаётся формой подключения HLS. Мультиформатный публичный каталог используется в REAL в режиме просмотра; внешние источники не получают фиктивных прав управления.

Проверено: `node --import tsx --test src/cameraCatalog.test.ts` (2 теста), `node node_modules/typescript/bin/tsc -b --pretty false`. Проверку фактического браузерного воспроизведения выполняет основной агент при общем QA; транспортные результаты в этом документе не подменяют её.
