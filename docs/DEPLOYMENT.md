# Подключение сервера и публикация

## Что запускается без ключей
Frontend и `/api/index?route=health` работают на Vercel. При отсутствии настроек базы health явно сообщает `mode: demo`. Учебные события, история действий и настройки камер сохраняются только в localStorage этого браузера. Не используйте этот режим для реальных служебных данных. Ошибка настроенного сервера не переключает рабочую базу на DEMO автоматически.

## Существующий Vercel-проект
1. Сохранить React/TypeScript/Vite, Node.js 24.x, Build Command `npm run build`, Output `dist`.
2. Публиковать ветку `feat/situation-center` как Preview. `api/index.ts` — серверная Node.js Function. Конфигурация исключает `/api` из SPA rewrite.
3. Проверить `/api/index?route=health`: JSON, не HTML. Секреты добавлять в Vercel Environment Variables, не в код/чат.
4. Production обновляется только после проверки preview и разрешения владельца. Старый deployment остаётся вариантом отката. Миграция создаёт новые таблицы; автоматически во время build она не запускается.

## База и роли
Подготовлена реализация для Supabase (PostgreSQL + PostGIS + Auth). Нужен отдельный проект; платные тарифы не подключались. У сервиса есть бесплатный план с ограничениями, актуальные условия: https://supabase.com/pricing. Альтернатива — самостоятельное размещение Supabase/PostgreSQL и Auth; это требует администрирования сервера. Для реальных служебных данных владелец должен выбрать допустимое место хранения и правила доступа.

1. Выполнить `supabase/migrations/001_situation_center.sql` в SQL Editor пустого проекта. Миграция выполняется транзакционно; повторно не запускать. Скрипт создаёт таблицы событий, камер, профилей, журнала, лимитов AI, индексы PostGIS, RLS и аудит-триггеры. DEMO-события в серверную базу не импортируются.
2. В Supabase Auth отключить публичную регистрацию; создать пользователей и настроить восстановление пароля. Новый пользователь получает только `observer` независимо от metadata.
3. Первый администратор назначается владельцем через SQL Editor по проверенному UUID: `update public.profiles set role='admin', display_name='Администратор' where id='<UUID из Auth>';`. Не назначать администратора всем пользователям.
4. В Vercel добавить `SUPABASE_URL` и `SUPABASE_ANON_KEY` (publishable/anon ключ проекта). Приложение не использует service-role key. Ключ остаётся на сервере; все запросы к данным выполняются с JWT пользователя и проходят RLS.
5. Перепубликовать deployment, проверить вход и три роли. Авторизация использует HttpOnly/SameSite=Strict cookie, Secure в production. Сессия — до одного часа, затем повторный вход. Пароль не сохраняется приложением.

## Настоящий AI
Сервер вызывает OpenAI Responses API; клиент не получает ключ. Доступ включается только при всех настройках: `OPENAI_API_KEY`, `OPENAI_MODEL` (доступная в аккаунте модель Responses), `AI_ENABLED=true`. Не включать до согласования расходов и передачи выбранных данных внешнему AI-провайдеру. Актуальная тарификация: https://developers.openai.com/api/docs/pricing. Альтернатива — отдельно согласованный адаптер к собственной модели; он не включён в эту реализацию.

AI получает только серверный снимок доступных пользователю событий: фильтры, рассчитанные агрегаты, до 150 записей (без полных описаний), ID и происхождение данных. `store:false`. Ответ показывает снимок и использованные записи; лимиты — 5 запросов/мин и 30/сутки на пользователя, атомарно в PostgreSQL. AI не выполняет записи и не вызывает инструменты. Без ключа выводится явная ошибка 503, фиктивного ответа нет. Авторизация и база обязательны, локальные записи в AI не передаются.

## Ограничения прототипа
- Серверная интеграция с реальным Supabase и реальной AI-моделью требует настройки и отдельного сквозного теста. Сейчас HTTP-тесты используют контролируемый mock внешнего сервиса.
- Аналитика загружает до 10 000 событий постранично; при превышении возвращает ошибку, а не неполный итог. Для дальнейшего роста нужна серверная агрегация. Каталог камер и аудит ограничены 1000 записями, журнал на экране — 100 последних загруженных действий.
- Проверка камеры — воспроизведение в текущем браузере, не непрерывный мониторинг. Проверка манифеста не доказывает наличие прямого эфира. Максимум 4 параллельных плеера на видеостене.
- PDF через системную печать: выбрать «Сохранить как PDF». CSV включает UTF-8 BOM, экранирование и защиту от формул.
- Тепловая карта не активирована: не подтверждены полнота и достоверность координат для такой интерпретации.
- Учебная сцена предыдущей версии сохранена в экспериментальном разделе отдельно от новой базы. Профили и форматирование телефона не используются для идентификации.
- Автоматические происшествия города, закрытые камеры и ведомственные базы не подключены.

## Проверки перед реальной эксплуатацией
После подключения: войти наблюдателем и убедиться, что изменение API/RLS запрещено; оператором создать и изменить событие; проверить аудит и конфликт версий в двух сессиях; администратором изменить роль и настройки камеры; убедиться в лимите AI и ссылках на записи; проверить истечение сессии и восстановление доступа. Проверить размещение/резервное копирование базы и срок хранения журнала. Это необходимые приёмочные проверки подключённых сервисов, а не заявление о готовности к ведомственной эксплуатации.
